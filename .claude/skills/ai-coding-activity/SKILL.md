## 일하는 방식

- 쪽 넘침 검사와 화면 캡처는 스스로 돌리지 않음. 사용자가 넘치는 쪽 번호를 알려 주며 해결을 요청했을 때만 그 쪽을 `scripts/measure_overflow.py`로 재고 고침
- 넘침을 고칠 때는 화면 밖으로 나간 것이 무엇인지 먼저 밝히고, 중요한 내용이면 쪽을 나누고 아니면 그 쪽 안에서 줄임
- 사용자는 쪽 번호를 표지를 1쪽으로 세어 말함
- 사용자와는 한국어 높임말로 대화함

## SQL 단계의 원칙

SQL 학습 활동에서 AI를 쓰는 목적은 정답을 얻는 것이 아니라 도움을 받는 것이다.

- 학생의 ChatGPT는 `references/ChatGPT 지침.md`대로 동작하므로, 활동도 그 지침에 맞춰 설계함
- 쿼리는 학생이 직접 작성하고, AI에게는 방향 · 해석 · 오류 원인 같은 도움만 구하게 함
- 정답 쿼리를 AI에게 받아 내는 프롬프트나 활동은 넣지 않음
- 직접 풀 수 있는 문제는 AI에게 묻지 않고 직접 푸는 것이 더 좋다는 점을 진행 방법에 밝힘

사용자가 LAB 번호를 알려 주면 아래 순서로 그 LAB에 맞는 문제를 찾아 목록으로 보여 준다.

1. SQL 수업 교안 폴더에서 해당 LAB 폴더를 찾는다

4. 찾은 문제를 수준이 쉬운 것부터 높은 순으로 나열한다
5. 사용자가 옮기라고 하면 `programmers_sql/[LAB-NN] 단원 이름/` 폴더를 만들고 그 LAB의 문제 파일을 `문제지/`에서 옮긴다. `문제지/`에 남은 파일이 아직 배정하지 않은 문제다

### 진행 방법의 다섯 단계

- ① 문제 읽기: 내 말로 정리함. AI 없이
- ② 직접 풀기: 풀 수 있으면 AI 없이 끝까지 품. 무조건 AI에게 묻지 않음
- ③ 방향 묻기: 막힐 때만 방향 묻기 템플릿으로 절과 순서를 받음
- ④ 힌트 확인: AI에게 받은 힌트를 쿼리로 써서 직접 실행해 확인함
- ⑤ 원인 묻기: 결과가 정답과 다르면 원인 묻기 템플릿으로 묻고, 고치는 것은 학생이 함

### 상황별 템플릿

- 프롬프트는 문제마다 만들지 않음. SQL 문제에 두루 쓰는 템플릿 두 개를 문제보다 먼저 제시하고, 이후 문제는 템플릿의 `{ }`만 바꿔 쓰게 함
- 학생이 문제나 학습 주제에 따라 바꿀 곳은 `{ }` 치환자로 묶음. 템플릿 쪽 오른쪽에는 「바꿀 곳 · 넣을 내용」 표를 둠
- 템플릿은 3단원에서 배운 다섯 섹션(`## 맥락` · `## 상황` · `## 질문` · `## 제약` · `## 출력 형식`)을 따름. 원인 묻기 템플릿은 한 화면에 넣으려고 `## 제약`을 뺐음
- 두 템플릿의 `## 상황`에는 `{테이블 이름} 테이블 구조: {DESC 실행 결과}` 줄을 둠. 학생에게 "테이블 명세"라는 말 대신 `myschool`에서 `DESC 테이블이름;`을 실행해 나온 결과를 그대로 붙이라고 안내함. 방향 묻기 템플릿은 DESC에 없는 컬럼 뜻을 `- 컬럼 뜻: {컬럼별 뜻}`으로 따로 적게 함
- 채운 프롬프트의 DESC 결과는 `mariadb -t`가 찍는 테두리 표(`+---+` · `| … |`) 모양으로 실음
- 템플릿 이름은 상황별로 지음. 「방향 묻기 템플릿 — 풀기 전에 내 이해를 점검받을 때」, 「원인 묻기 템플릿 — 실행 결과가 정답과 다를 때」

### 문제 1 (시연)

학생 입장에서 처음부터 끝까지 따라가는 시연이다. 쪽 순서는 아래와 같다.

1. 문제 원문(테이블 설명 · 구조표 · 문제 상자)
2. 입출력 예시
3. 방향 묻기 프롬프트 작성: 템플릿을 문제에 맞게 채운 프롬프트(`<Prompt cols="2">`)
4. 방향 묻기 프롬프트 점검: 「바꿀 곳 · 넣은 내용」 표와 DESC 결과 · 컬럼 뜻 안내. 프롬프트에 DESC 표가 들어가 한 쪽에 넣을 수 없어 나눴음
5. 방향 묻기 AI 답변 예시
6. 직접 풀고 결과 확인하기: 순서표를 주석으로 옮겨 쓴 쿼리, 실행 전 예측, 내 실행 결과, 정답 결과 표. 다음 쪽으로 이어지도록 쿼리는 일부러 틀리게 씀
7. 원인 묻기 프롬프트 작성: 틀린 쿼리 · 기대한 결과 · 실제 결과를 그대로 넣은 프롬프트
8. 원인 묻기 AI 답변 예시

- AI 답변 쪽에는 「이 쪽은 예시다」 경고 상자를 두고, 같은 프롬프트라도 답이 매번 달라진다는 점을 밝힘
- 답변 예시는 `references/ChatGPT 지침.md`를 따르는 모양으로 씀. 쿼리를 주지 않고, 개조식 음슴체, 표, 추론 표시, 「내가 확인할 점」을 갖춤
- 시연에 쓰는 실행 결과(틀린 쿼리의 결과와 정답 결과)는 `myschool`에서 직접 실행해 확인한 값만 실음
- 고친 뒤의 정답 쿼리는 덱에 싣지 않음. 시연은 "내가 고쳐서 다시 실행한다"로 끝남

### 문제 2 이후

- 문제와 입출력 예시만 실음. 프롬프트 예시는 넣지 않음
- 쪽 수는 제한이 없음. 길면 「입출력 예시 (1)」 · 「(2)」로 나눔
- 문제 쪽은 왼쪽에 테이블 설명, 오른쪽에 구조표, 아래에 「문제」 상자를 둠. 수준과 문제 번호는 상자의 `tag`에 적음(`Level 1 · 프로그래머스 59034`)
- 문제 원문과 입출력 예시는 문제지의 글을 그대로 옮김. 다만 "본 문제는 Kaggle의 …"처럼 출처 · 라이선스를 밝히는 문장은 싣지 않음. 학생이 프로그래머스 페이지에서 직접 확인할 수 있음
- `scripts/gen_problem_slides.py`로 문제지 폴더에서 한꺼번에 만듦

  ```bash
  python3 .claude/skills/ai-coding-activity/scripts/gen_problem_slides.py \
    "programmers_sql/[LAB-02] 데이터 조회하기" 59034,59403,59035 2 5 /tmp/problems.md
  ```

  인자는 문제 폴더, 쉬운 순서의 문제 번호 목록, 첫 문제의 순번, 첫 문제의 절 번호, 출력 파일이다. 출력 내용을 덱의 「감사합니다」 쪽 앞에 붙이며, 앞쪽과의 사이에 쪽 구분선 `---`이 있는지 확인한다

### 정답 확인

- 정답 확인은 프로그래머스 제출이 아니라 로컬 실행으로 함. 학생이 `myschool`에서 실행한 결과를 정답 결과와 비교함
- 문제 1에는 「정답 결과」 표가 있음. 문제 2~16에는 사용자의 요청대로 문제와 입출력 예시만 있고 정답 결과 표는 없음. 필요한지는 사용자에게 확인해야 함

### 쪽 작성 규칙

- HTML 주석(강사 원고)은 넣지 않음. 사용자가 3단원 덱에서 모두 지우게 했음
- 사이드바는 간지를 맨 왼쪽에, 그 아래 `##` 쪽과 `###` 쪽을 차례로 들여 써서 보여 줌
- 쪽 제목은 `—` 앞부분만 사이드바에 표시됨. 같은 절 안에서 `—` 앞부분이 쪽마다 달라야 함. 예: 「방향 묻기 프롬프트 작성 — …」, 「방향 묻기 AI 답변 예시」
- `<style>` 블록과 `style=""` 속성을 쓰지 않고 테마 컴포넌트(`Callout` · `Chip` · `Core` · `Flow` · `Grid` · `Output` · `Prompt` · `Stat` · `Steps` · `Tile` · `Timeline`)와 UnoCSS 유틸리티로 해결함
- 한 쪽은 16:9 한 화면을 넘지 않게 함. 프롬프트 상자는 `class: dense` 쪽에서 17줄까지 들어가고, 더 길면 `<Prompt cols="2">`로 두 단으로 흘림
- `Tile`은 제목과 본문이 있으면 높이가 190px쯤 되고, 표는 한 행이 45px쯤임. 한 쪽에 상자를 네 줄 이상 쌓으면 넘치기 쉬움
- 줄 맨 앞에 `<Chip>`을 두면 문단이 사라지므로 줄 전체를 `<p>`로 감쌈
- 학생이 채울 자리는 `{내가 쓴 쿼리}`처럼 중괄호로 씀. 프롬프트 상자 안에서는 테마가 노란 굵은 글씨로 칠함
